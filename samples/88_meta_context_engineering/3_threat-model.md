# Threat Model: Autonomous Flight Delay Refund System

**Document Type:** Compiler Instruction Set — Attacker Directives & Boundary Constraints  
**Scope:** Refund Policy Agent (User Space) and DIR Kernel Space  
**Dual Purpose:** 
1. Hard constraints for the Developer Agent during code generation.
2. Attack playbook for the Adversarial QA Agent during CI/CD execution.

---

## 1. Security Posture & Assumptions

We operate under a strictly partitioned **Zero Trust** model.
- **Assumption 1 (Compromised Reasoning):** The Agent (`refund_policy_agent_v1`) is inherently malicious, hallucinating, or fully hijacked via Prompt Injection. Its output (`RefundProposal`) MUST ALWAYS be treated as an untrusted, hostile payload.
- **Assumption 2 (Hostile Data):** Passenger APIs and incoming `FlightDelayEvent` payloads are manipulated.
- **Assumption 3 (Network Hostility):** The Payout API will drop connections, time out, and return ambiguous 500 errors.

---

## 2. Generation Constraints (Developer Agent "Physics")

The Developer Agent generating the code MUST adhere to the following deterministic security boundaries. Any violation will result in compilation failure.

| Rule | Constraint |
|------|------------|
| **SEC-1** | **No Direct I/O in User Space:** The Refund Policy Agent MUST NOT import `requests`, `httpx`, or any database client. It cannot execute the payout. |
| **SEC-2** | **Immutable Validation:** The Proof Checker logic MUST NOT accept any dynamic configuration, prompt overrides, or LLM-based heuristic evaluation. Hashes and signatures are verified via standard cryptographic libraries. |
| **SEC-3** | **Enforced Idempotency:** The Execution Engine MUST NOT trigger a payout without first generating and validating a deterministic Idempotency Key: `SHA256(DFID + Step_ID + Canonical_Params)`. |
| **SEC-4** | **No Shared Memory:** The Agent MUST NOT use global variables to remember previous flows. All state retrieval MUST pass through the explicit Context Compiler. |

## 3. Adversarial Traps (QA Agent Playbook)

During the CI/CD pipeline, the Adversarial QA Agent MUST execute the following deterministic attacks against the generated codebase. If the system executes a payout under any of these conditions, the build FAILS.

### Trap 1: The TOCTOU (State Drift) Attack
* **Attack Vector:** The system compiles the `WorkingContext` at $T_0$. The Agent proposes a 500 EUR refund. Before the Proof Checker validates the PCI at $T_1$, the Attacker mutates the underlying `CompensationPolicy` in the authoritative DB to lower the maximum refund to 300 EUR.
* **Expected Defense:** The Proof Checker MUST reject the PCI with a `STATE_DRIFT_DETECTED` error because the JIT live state hash no longer matches the `context_ref` snapshot hash.
* **Success Criteria:** 0 EUR paid out. Flow aborted or returned to Agent for re-evaluation.

### Trap 2: Replay Attack (Execution Chaos)
* **Attack Vector:** A perfectly valid, correctly signed, and fully authorized `ProofCarryingIntent` is intercepted and submitted to the Execution Engine 10,000 times concurrently.
* **Expected Defense:** The Idempotency Key dictates this is functionally the same intent. The Decision Ledger accepts the first commit and rejects all 9,999 subsequent commits. The Execution Engine fires exactly once. 
* **Success Criteria:** Exactly 1 payout transaction triggered via the downstream API.

### Trap 3: Cryptographic Forgery (The Greedy Passenger)
* **Attack Vector:** The Attacker intercepts a valid `ProofCarryingIntent` generated by the Agent. The initial payload states `amount_eur: 250`. The Attacker modifies the JSON to `amount_eur: 2500` and submits it to the Kernel.
* **Expected Defense:** The Proof Checker's Identity Attestation MUST fail. The `roa_signature` no longer matches the mutated `intent_payload`. 
* **Success Criteria:** PCI rejected. Incident logged. No execution.

### Trap 4: The Transient Network Ambiguity
* **Attack Vector:** The Execution Engine sends the payout request to the mock Payout API. The API processes the payment but the TCP connection drops before returning the HTTP 200 OK. The system retries.
* **Expected Defense:** The system MUST forward the deterministic Idempotency Key to the Payout API upon retry, ensuring the external bank does not process a duplicate ledger entry.
* **Success Criteria:** Agent does not retry reasoning. Downstream system recognizes the retry and ignores it.

### Trap 5: Poisoned Evidence Loop
* **Attack Vector:** The Attacker submits a `FlightDelayEvent` with `delay_minutes = -5000` (physically impossible) or injects instructions into the passenger name: `"John \\" DROP TABLE passengers; --"`.
* **Expected Defense:** Context Compiler correctly casts types and sanitizes data. The Agent either explains why the wait time is invalid or processes the malicious string peacefully as narrative context. The Kernel does not execute SQL based on prompt text.
* **Success Criteria:** Graceful rejection. No SQL injection. No system crash.

## 4. Failure Modes & Circuit Breakers

If the Proof Verification fails fundamentally (e.g., missing public keys in Agent Registry, corrupted Context Store), the system MUST default to **FAIL THE FLOW (DIRTY)**. 
- The system MUST NOT attempt to dynamically "guess" the keys or ask the Agent what to do next.
- The system MUST NOT "fail open" and allow unverified intents to bypass the Ledger.
